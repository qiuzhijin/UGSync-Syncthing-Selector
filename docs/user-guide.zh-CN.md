# UGSync · Syncthing 详细使用手册

适用版本：Windows 中文界面 V16 预览版。核对日期：2026-11-14；已验证同步引擎：Syncthing v2.1.7。

“最近完成”包含引擎扫描发现的本地文件/文件夹删除，标为“本地已删除（未核对对端）”；这不代表 NAS 已执行删除。扫描前、未同步范围内，或事件缓冲已丢失的历史删除不会被补记。远端同步到本机的删除仍显示“已同步删除”。该列表不是完整操作审计日志。

本手册使用通用示例，不包含作者的设备身份和访问密钥。路径、账号和端口请按实际环境调整。

## 1. 软件组成与使用边界

| 组成 | 位置 | 作用 |
| --- | --- | --- |
| Syncthing Docker | NAS | 扫描 NAS 数据、传输、冲突处理及按配置保留旧版 |
| Syncthing Windows 引擎 | Windows，预览包内提供 | 扫描本机文件、传输及版本处理 |
| UGSync 中文界面 | Windows | 目录树选择、启停、进度、托盘与自启动 |

文件在两个引擎之间同步，中文界面通过本机 REST API 进行管理。初次配对、添加任务、版本恢复以及高级网络和带宽设置仍使用 Syncthing 网页。

适用场景：NAS 保留资料，每台电脑只选择需要的目录，选中范围内可以双向修改。没有在线占位文件，勾选后下载实际内容，会占用本地空间。取消勾选不会自动释放空间。

**同步不是独立备份。** 本方案会传播同步范围内的删除；版本控制需主动启用，且不能记录每一次本地编辑。先用可丢弃文本验收，再接入正式资料。

同一目录不要同时让旧 UGSync、另一份 Syncthing 或其他同步软件执行双向写入。当前方案不需要安装旧 UPK 或权限辅助服务；旧方案的移除与清理需另行确认，不能直接删除旧暂存区或版本库。

## 2. 环境与目录规划

### 2.1 准备条件

- Windows x64 桌面环境；当前未提供所有 Windows 版本的正式兼容矩阵，以实测为准。
- NAS 可运行 Docker，所用账号对目标目录有读写权限。
- 两端可通过局域网、直连或 Syncthing 发现与中继机制建立连接。
- 系统时间正常，数据目录和版本库均有足够空间。
- 首次试用使用专用空目录；正式资料另有独立备份。

### 2.2 示例

| 含义 | 示例 |
| --- | --- |
| NAS 宿主数据目录 | `/volume2/Drive` |
| 容器内数据目录 | `/data` |
| NAS 配置持久目录 | `/volume2/docker/Syncthing/config` |
| Windows 数据目录 | `E:\Drive` |
| 两端共同文件夹 ID | `ugsync-drive` |
| 任务显示标签 | `Drive` |

两端的**文件夹 ID 必须相同，路径不必相同**。NAS 网页填写容器内的 `/data`，不要填容器中不存在的宿主路径。不要首次就把两个内容不同的资料库直接合并，先走测试流程。

## 3. NAS Docker 部署

### 3.1 已有容器用户

已有 Syncthing 就直接接入，不要因容器名称不同而重复部署。以下命令只查看当前运行容器：

```sh
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
```

把 `YOUR_CONTAINER` 换成实际名称，查看卷映射和引擎版本：

```sh
docker inspect YOUR_CONTAINER --format '{{range .Mounts}}{{println .Source "->" .Destination "RW=" .RW}}{{end}}'
docker exec YOUR_CONTAINER syncthing --version
```

核对配置和数据均映射到持久位置，数据映射可写。保留已有身份、配对、目录规则和版本配置，不需要重新生成身份。

### 3.2 用 NAS 图形界面新建

以 LinuxServer 的 Syncthing 镜像为例：

1. 创建配置目录与空测试数据目录。
2. 下载 `lscr.io/linuxserver/syncthing` 镜像，先验证所选版本；正式运行记录并固定标签或摘要。
3. 设置 `PUID`、`PGID` 为实际资料账号的 UID/GID。NAS 执行 `id YOUR_USER` 查询，不要照搬他人的数值。
4. 配置目录映射到 `/config`，数据目录映射到 `/data`，设置读写。
5. 映射下面说明的端口，设置容器自动重启，启动容器。

不需要特权容器或递归 `chmod 777`。账号权限、数据卷和 UID/GID 应相互匹配。LinuxServer 与官方 `syncthing/syncthing` 镜像的配置路径和默认用户不同，不要混用模板。[LinuxServer 官方部署说明](https://docs.linuxserver.io/images/docker-syncthing/)

### 3.3 端口含义

| 容器端口 | 用途 | 注意 |
| --- | --- | --- |
| `8384/tcp` | 网页管理 | 不是文件传输端口，不直接暴露公网 |
| `22000/tcp`、`22000/udp` | 设备同步连接 | 直连需匹配宿主端口、地址和防火墙 |
| `21027/udp` | 局域网发现 | 受 Docker 网络及广播环境影响 |

若 NAS 自动分配宿主端口，例如 `44833 → 8384`，浏览器使用宿主 `44833`。实际值看自己的容器映射，不能照搬别人截图。

### 3.4 可选 Compose 示例

已有容器可跳过。此例使用 LinuxServer 镜像，**与仓库 `deploy/syncthing/compose.yaml` 的官方镜像模板不同**，不要覆盖现有部署。

修改 UID/GID 和宿主路径后使用。`latest` 来自上游示例，适合首次试用，但会变化，不代表固定的 v2.1.7；正式运行应替换为自己验证过的标签或摘要。

```yaml
services:
  syncthing:
    image: lscr.io/linuxserver/syncthing:latest
    container_name: syncthing
    hostname: nas-sync
    environment:
      PUID: "1000" # 示例，替换为自己的 UID
      PGID: "1000" # 示例，替换为自己的 GID
      TZ: Asia/Shanghai
    volumes:
      - /volume2/docker/Syncthing/config:/config
      - /volume2/Drive:/data
    ports:
      - "127.0.0.1:8384:8384"
      - "22000:22000/tcp"
      - "22000:22000/udp"
      - "21027:21027/udp"
    restart: unless-stopped
```

将示例保存为新部署目录中的 `compose.yaml`。第一条命令检查配置，第二条拉取所需镜像并创建/启动容器：

```sh
docker compose config --quiet
docker compose up -d
```

此例将管理端口只绑定 NAS 本机。电脑通过 SSH 转发访问，替换真实账号和 NAS 地址：

```sh
ssh -N -L 18384:127.0.0.1:8384 YOUR_USER@NAS_HOST
```

保持终端运行，浏览器访问 `http://127.0.0.1:18384`。这表示 NAS 网页；电脑自身的管理页仍是 `http://127.0.0.1:8384`。已有 NAS 图形部署如果允许可信局域网访问，可使用其实际管理地址，并设置管理身份验证和访问限制。

### 3.5 NAS 首次设置

打开 NAS Syncthing 网页，设置管理用户名和密码，确认配置持久化。从“操作 → 显示 ID”取得 NAS 设备 ID，稍后配对。无需保留的默认任务只移除配置、保留磁盘数据；未确认前不要选择删除数据。

## 4. Windows 安装和连接

### 4.1 完整解压

1. 获取项目发布的 Windows x64 预览包。当前本地候选为 `UGSync-Syncthing-Preview-20261113-v9.zip`，公开地址以维护者实际发布为准。
2. 完整解压到固定目录，如 `D:\Apps\UGSync-Syncthing-Selector`，不要在压缩软件中直接运行或只取出 EXE。
3. 运行 `UGSync-Syncthing-Selector.exe`，无需安装 Python。
4. 本机引擎已运行则连接，否则尝试启动随包引擎并等待配置生成。

随包引擎位于 `_internal\engine`。运行路径不应频繁变化，尤其是启用自启动后。程序只允许当前用户一个界面实例，重复运行会唤醒旧窗口；升级前请从托盘退出旧版。

### 4.2 本机管理页和密钥

浏览器访问 `http://127.0.0.1:8384`，这是 Windows 本机 Syncthing 网页。检查初次生成的默认任务，不要误当作 NAS 的 Drive。防火墙授权按实际可信网络配置，不要把管理端口改到公网来解决配对。

中文界面优先点击“连接本机（自动读取配置）”。默认从当前用户 `%LOCALAPPDATA%\Syncthing\config.xml` 读取回环管理地址和 API 密钥，密钥仅在内存中使用。

自定义配置位置或端口时，在**本机**网页查看管理地址和 API 密钥，手动填写后点击“连接并读取同步任务”。NAS 地址和 NAS API 密钥是可选的只读动态功能，只有需要在托盘查看 NAS 实时下载清单时才填写；它们不用于配对或修改 NAS 配置。NAS 地址保存在当前 Windows 用户设置，NAS API 密钥保存在 `%LOCALAPPDATA%\UGSync\syncthing-nas.json`，该目录不在同步根目录；清空密钥框并离开输入框即可删除当前 NAS 的已保存密钥。设备 ID 是配对标识，不是 API 密钥；不要把密钥贴到 Issue、聊天或截图。

## 5. 配对与首次任务配置

### 5.1 双方添加设备

1. Windows 网页“操作 → 显示 ID”取得电脑 ID。
2. NAS 网页“添加远程设备”，填写电脑 ID。
3. Windows 网页“添加远程设备”，填写 NAS ID。
4. 保存，等待设备连接，确认没有把自己的 ID 当成对端 ID。

设备连接与目录共享是两个步骤，接着配置同一个文件夹 ID。[上游配对流程](https://docs.syncthing.net/intro/getting-started.html)

### 5.2 首次选择性下载：先预置全部忽略

在**新的空 Windows 目标目录**中，先创建 UTF-8 编码的 `.stignore`，只有一行：

```text
*
```

目标为 `E:\Drive` 时，文件必须是 `E:\Drive\.stignore`，不是 `.stignore.txt`。在接受共享或添加任务前准备，避免尚未选目录就下载全部资料。

已有任务的忽略文件不能直接覆盖：先备份并核对原规则。忽略规则仅作用于本设备，且按顺序匹配；它不会自动复制到 NAS 或其他电脑。[忽略规则说明](https://docs.syncthing.net/users/ignoring.html)

### 5.3 NAS 添加文件夹

| 字段 | 示例 |
| --- | --- |
| 标签 | `Drive` |
| 文件夹 ID | `ugsync-drive` |
| 路径 | `/data` |
| 类型 | 发送与接收 |
| 共享 | 勾选对应 Windows 设备 |
| 版本控制 | 简单版本控制，保留 10 版，按需调整 |

NAS 保持运行并扫描。通常 NAS 保留完整共享资料，不复制电脑的选择性忽略规则。

### 5.4 Windows 接受共享

在本机网页接受 NAS 文件夹，或手动添加：ID 与 NAS 相同，本地路径为已预置 `.stignore` 的 `E:\Drive`，类型“发送与接收”，共享设备选择 NAS，分别开启简单版本控制。

Windows/Linux 混用时可按需要启用任务高级选项中的“忽略权限”，减少平台权限差异；它不会授予 NAS 账号本来没有的访问权限。

允许任务运行以交换索引，确认 `*` 仍阻止全部业务下载。再回中文界面连接本机并选择 `Drive`。NAS 初次扫描需时间，目录树为空时检查扫描、设备连接和共享。

版本控制是**按设备、按文件夹**设置，NAS 开启不代表电脑也开启。它保留收到远端替换或删除前的旧版，不能记录每次本地修改。[版本机制](https://docs.syncthing.net/users/versioning.html)

## 6. 树形选择同步目录

### 6.1 选择示例

可以直接展开目录，勾选需要的子目录，不必先选父目录。父目录全部同步显示对勾，部分同步显示蓝色实心方框，未选择显示空框。展开箭头只加载子目录，不改变选择。下面的“先选父目录”仅适用于希望包含整个父目录再排除例外的操作。

假设目录为：

```text
Drive/
├─ 工作/
│  ├─ 项目A/
│  └─ 临时/
│     └─ 需要保留/
└─ 照片/
```

希望同步工作、排除临时、重新包含需要保留：

1. 选择任务，取消“同步整个根目录（包含以后新增的目录）”。
2. 勾选“工作”，展开后取消“临时”。
3. 展开“临时”，再勾选“需要保留”。
4. 点击“预览并保存选择”，核对旧规则和新规则，确认保存。
5. 保存后任务保持暂停；点击“继续同步”生效。

父目录包含其未来新增子目录，更具体的子项选择覆盖父项。重新操作父项会重置其下面的选择，因此先选父目录，再设置子目录例外。

### 6.2 根目录全选

“同步整个根目录”包含根目录及未来正常新增内容，仍受原有排除规则约束。也可以全选根目录后排除某个分支。

关闭根目录全选、只选“工作”时，根目录的直接文件会随包含该子目录的选择一起同步；未选分支的子目录内容不会一起包含。同样地，选择“工作/项目”时，“工作”目录直接放置的文件也会同步，而“工作”下未选的兄弟子目录仍不会同步。当前以目录为选择单位，不提供逐个文件勾选。

### 6.3 保存为什么暂停

界面先核对规则，再暂停任务、发布新规则并回读，保存后保持暂停，让用户明确继续。保存失败时先保持暂停并重新连接核对，不要连续重试或同时在网页修改规则。

### 6.4 取消选择的含义

取消勾选只停止该路径在本机参与同步，已下载文件保留，不会自动删除或变成云端占位文件。忽略期间两端都修改过文件，再次勾选可能产生差异或冲突。

取消勾选不等于安全清理缓存。需要释放空间时，应先核对规则已生效、NAS 存在完整副本，再另行确认清理范围。

### 6.5 灰色目录与规则限制

已有纯排除规则保留并优先生效；能精确识别的固定目录排除项可能显示灰色，复杂通配规则不一定都标灰。外部 `#include` 或反选包含规则可能导致界面拒绝接管，应在引擎网页备份并核对，不要直接清空。

父节点目前不是三态复选框：它表示该分支默认选择，子项可有例外。确认前展开相关分支并核对预览。

### 6.6 暂停时树为空

暂停任务时当前引擎不提供目录树，保存规则仍会保留。编辑树前要恢复并重新读取；首次场景先确保 `*` 生效再恢复。正式任务恢复后会按已有范围同步，不能把恢复当成纯查看动作。

## 7. 进度与托盘动态

### 7.1 操作

| 操作 | 效果 |
| --- | --- |
| 左键单击图标 | 打开同步动态小面板 |
| 双击图标 | 打开目录选择窗口 |
| 右键图标 | 打开窗口或明确退出 |
| 点击面板外 | 收起面板，同步继续 |
| 关闭主窗口 | 托盘可用时收起，继续同步 |

图标可能在 Windows 右下角 `^` 隐藏图标区域，可在任务栏设置中调整显示位置。

### 7.2 总体进度

面板跟随主窗口当前选定任务，取本机与共享设备中较慢一端的完成比例。本机没有待下载内容，并不代表 NAS 已收完。

| 显示 | 含义 |
| --- | --- |
| 正在上传 | 本机正在向已连接对端传输，顶部显示上传速度及对端待接收总量 |
| 正在下载 | 本机正在从已连接对端接收内容 |
| 正在上传和下载 | 两个方向同时有待处理内容 |
| 正在同步 | 仍有内容或项目待处理，但当前未能归入单一传输方向 |
| 正在扫描 | 正在发现本地变化，不能当作传输百分比 |
| 正在核对文件索引 | 索引、属性或项目仍需核对 |
| 等待设备连接 | 部分共享设备离线，不能确认双方完成 |
| 已暂停 | 当前任务暂停，需要继续 |
| 已同步，两端完成 100% | 统计确认双方完成，本机处于空闲 |
| 状态暂时不可用 / 同步出错 | 检查引擎、网络、文件错误、空间及权限 |

客户端不会只凭状态摘要中的错误计数显示“同步出错”；当计数非零时，会进一步读取该文件夹的错误详情。详情为空时仍显示实际同步进度，避免旧计数造成误报。

约每 5 秒刷新。百分比按索引统计，大文件可能处理完成后才变化，不是逐块进度或剩余时间预测。速度为**本机整个引擎的总速度**，含其他任务和协议开销，不是单文件速度；初次连接或计数重置会显示采样。

### 7.3 文件动态标签

| 标签 | 内容 | 限制 |
| --- | --- | --- |
| 正在传输 | 本机 Syncthing 确认正在下载的文件；填写 NAS 只读地址和密钥后，也显示 NAS 确认正在下载的文件 | Syncthing 公开 API 不提供“当前上传字节属于哪个文件”的可靠清单 |
| 等待队列 | 本机等待下载、等待上传至对端，以及（可选）NAS 等待下载 | 每端每页 30 项，可翻页；队列不是正在传输列表 |
| 最近完成 | 引擎缓存的接收、删除、属性更新；本次运行确认的对端完整接收 | 不是所有已同步文件数据库，也不保证捕获两次刷新间每次上传 |
| 通知 | 缓存中的文件错误与动态读取错误 | 旧错误可能已经恢复，需结合当前状态 |

“等待上传至对端”不保证此刻正在上传。对观察到的上传，只有核对同一版本及远端完整副本后才显示“已确认对端接收”，不单凭队列消失判定。NAS 动态读取的是 NAS 自己的 `db/need` 状态；NAS 可能从本机或其他设备获取内容，因此界面只显示“来源由 NAS Syncthing 选择”，不猜测来源。

上传完成记录仅存本次界面运行的内存，退出后不保留；接收记录受引擎缓存限制。读取失败会清空旧清单并提示。面板只读，不改文件、任务或选择规则。

### 7.4 资源管理器同步角标

勾选“资源管理器同步角标”即可启用。首次启用时，客户端会先检测 Explorer 扩展；未安装则弹出 Windows UAC 管理员授权，自动校验并安装随包的 DLL、图标和注册项，然后开始发布蓝色（同步中或部分选择）、绿色（已同步）和红色（已明确排除、暂停或错误）角标。取消勾选只停止状态发布，不会卸载已安装的扩展。

安装后 Explorer 可能仍保留旧的图标处理程序；此时请注销 Windows 后重新登录。安装被拒绝、组件不完整或注册名被其他软件占用时，复选框会自动取消并显示原因；不会修改其他软件的角标注册项。

## 8. 日常操作与自启动

### 8.1 编辑、暂停和继续

在选中目录中正常编辑，保存关闭文件后留时间给引擎扫描和传输。等待重要资料两端完成再关机。临时 Office 文件、缓存、数据库等是否排除，应按应用方式决定；这不是多人实时协作编辑。

主窗口暂停/继续针对当前任务，不是 NAS 全部任务或全部电脑。“刷新状态”不解除暂停。带宽、发现、中继等高级选项在本机引擎网页设置，中文界面当前没有这些设置页。

### 8.2 登录自动启动

勾选“登录 Windows 后自动启动并收起到右下角托盘”，设置当前用户登录启动，不是登录前运行的系统服务，也不控制 NAS 启动。默认不会替用户开启。

启用后保持程序位置不变；移到新位置后重新勾选。取消时仅移除本程序的当前用户启动项，不改其他软件。

### 8.3 退出

托盘“退出（同时停止同步）”先关闭**本机引擎**再退出界面，NAS 容器继续运行。即使引擎原先已独立运行，该菜单也会请求关闭它，影响同一引擎的全部本机任务。

关闭请求失败时保留界面并提示；关闭主窗口不等于停止。再次启动会连接或启动引擎。

## 9. 删除冲突与版本恢复

### 9.1 删除传播

在已选且未忽略范围删除文件，通常会传播到另一端。与旧自研方案的“删除暂不传播”不同。不要假定 Docker 删除都会进入 NAS 回收站，回收站与 Syncthing 版本库不是同一机制。

### 9.2 开启和恢复版本

两端分别编辑任务，启用简单版本控制，设置保留数量，如 10。默认版本目录通常为 `.stversions`，除非另有配置，需额外空间。不要把版本目录加入额外业务同步任务，也不要未经核对直接删除。[上游版本文档](https://docs.syncthing.net/users/versioning.html)

恢复步骤：

1. 停止编辑目标，必要时另存当前版本。
2. 打开保有旧版那一端的引擎网页，找到文件夹版本/恢复入口。
3. 核对路径和时间点后恢复，等待扫描与同步。
4. 检查原路径和对端收到的内容。

入口名称随上游语言/版本可能变化，当前中文界面不直接提供版本恢复按钮。不要手工覆盖版本库索引。仅开启本机版本控制不能保留每次本机修改前内容，仍需独立备份。

### 9.3 同时修改冲突

离线或未同步完成时分别改同一文件，可能产生带 `sync-conflict` 名称的副本。保留原件和全部副本，分别比较并另存备份，人工合并确认后保存最终内容，再等待两端完成。

确认内容齐全后才决定清理副本；删除副本也可能传播。不要仅凭时间戳判断哪份正确，本方案不保证自动合并或冲突后暂停整个任务。

## 10. 多台电脑与外网连接

新增电脑单独配对，在 NAS 同一任务中共享给它，使用相同文件夹 ID。每台电脑有自己的本地路径和忽略规则，例如一台选择工作，另一台选择照片。NAS 通常保留完整共享资料，新电脑仍先阻止全量下载再设置范围。

在引擎网页设备详情查看连接类型和地址。自动发现、中继和直连取决于 Docker 映射、路由、防火墙及设置；中继可用不代表速度等同局域网。

若容器 `22000/tcp` 映射为宿主 `33521`，手动 TCP 地址应为 `tcp://NAS_HOST:33521`，不能填管理端口。固定地址须使用自己真实映射。不要为提速暴露管理页到公网。[网络与防火墙参考](https://docs.syncthing.net/users/firewall.html)

## 11. 升级备份与卸载

### 11.1 升级 Windows

1. 等待重要资料完成，从托盘明确退出旧版。
2. 备份资料、引擎配置和每个任务的 `.stignore`。
3. 完整解压新版，不混用旧 `_internal` 或只替换 EXE。
4. 启动并检查设备身份、任务路径、规则和版本控制，做小文本双向测试。
5. 若程序位置变化，重新设置自启动。

界面升级不要求删除配置重新配对。引擎版本变化时核对上游升级说明，不能假定任意数据库格式都允许降级。

### 11.2 NAS 升级与备份

记录镜像版本、端口、UID/GID 和卷映射，备份持久配置，再按镜像说明更新并保留原卷。不能让两个容器同时使用同一引擎配置库。重建后核对设备 ID、共享任务和规则，再验收修改与恢复。

| 备份内容 | 注意 |
| --- | --- |
| 业务资料 | 使用独立备份介质或系统 |
| NAS 配置持久目录 | 含身份材料；停容器或使用可靠快照备份，妥善保管 |
| Windows 实际配置与数据位置 | 默认配置入口 `%LOCALAPPDATA%\Syncthing`，自定义位置以引擎为准 |
| 各任务 `.stignore` | 每台设备不同，应分别备份 |
| 版本库 | 受空间、数量和保留期限制，不替代独立备份 |

### 11.3 卸载

取消自启动、明确退出，再移除不需要的任务配置并选择保留磁盘文件，最后决定程序/容器是否删除。删程序不等于删资料，删配置可能需要重新配对。

目录被占用时检查界面、引擎、编辑器和终端的使用，不要强制递归删除资料目录。不要将配置或身份备份上传到公开仓库。

## 12. 常见问题

| 现象 | 检查和处理 |
| --- | --- |
| 响应读取失败或超时 | 本机网页能否打开；引擎运行情况；端口和本机 API 密钥是否正确 |
| 找不到引擎 | 完整解压，保留 `_internal\engine`，不要单独移动 EXE |
| 重复运行没有新窗口 | 单实例会唤醒旧窗口，检查托盘；新版先退出旧版再运行 |
| 设备连接但没有任务 | 检查文件夹共享、电脑是否接受、双方文件夹 ID |
| 树为空 | 检查暂停、NAS 扫描和设备连接；首次先确保 `*` 生效再恢复 |
| 目录灰色 | 可能受原排除规则限制，先备份核对，不直接清空规则 |
| 保存后停了 | 预期行为，核对后点继续 |
| 勾选但没下载 | NAS 完整副本、忽略规则、共享对象、任务暂停和磁盘空间 |
| 本机待接收为零但没完成 | NAS 或其他共享设备仍在处理，检查对端统计 |
| 大文件百分比不动 | 结合速度、错误和空间判断，索引百分比可能完成后才更新 |
| 最近完成没有旧文件 | 这里是有限缓存和本次运行记录，不是完整历史 |
| 通知有旧错误 | 可能已经恢复，结合当前状态和引擎错误详情 |
| NAS 权限错误 | 检查数据卷、实际 UID/GID 和权限，不照搬数字或递归放宽全部权限 |
| 删文件后另一端也没了 | 删除传播，从有版本的一端恢复并核对保留策略 |
| 关窗口还在同步 | 收起托盘属预期，要停止请明确退出 |
| 退出后其他任务也停了 | 本机所有任务共享同一引擎，退出会关闭它 |
| 重启后要求重新配对 | 检查是否丢失持久配置、换了配置路径或 Windows 用户 |

反馈时提供版本、环境、最小步骤、期望和实际表现、脱敏错误。不要提供原始配置、API 密钥、Cookie、密码、私钥或业务文件。
