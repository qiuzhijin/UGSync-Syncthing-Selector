# NAS 目录服务试用

UGSync 可以用独立的 HTTPS 目录服务读取 NAS 上实际存在的文件和目录。每次请求只读取当前目录的直属条目，Syncthing 继续负责同步文件。未配置目录服务的客户端继续使用原来的目录读取方式。

## NAS 端

1. 将 `deploy/catalog` 复制到 NAS，进入该目录。配置环境变量 `SYNCTHING_DATA`（与 Syncthing 共享文件夹对应的 NAS 宿主机绝对路径）、`UGSYNC_CATALOG_FOLDER`（Syncthing 文件夹 ID）和 `UGSYNC_CATALOG_TOKEN`（至少 32 个可打印 ASCII 字符的独立随机令牌）。如有需要，设置 `NAS_UID` 和 `NAS_GID` 为有只读访问权限的账号 ID。
2. 运行 `docker compose up -d`。数据目录以只读方式挂载，宿主机端口仅绑定 `127.0.0.1:8788`。
3. 外网试用时，由能访问该监听地址的 HTTPS 反向代理转发 `/v1/list`，保留 `Authorization` 请求头及查询参数。客户端要求可信的 HTTPS 证书。只在同机开发测试中使用回环 HTTP 地址。

## Windows 客户端

先连接本机 Syncthing 并选择同步任务，再打开「设置 → NAS 目录服务」，填写 HTTPS 站点地址和目录服务令牌，点击「测试并启用」。测试会读取当前任务的根目录，成功后保存到本机。令牌独立于 Syncthing API 密钥。通过「停用目录服务」可恢复原来的目录读取方式。

尚未在界面保存目录服务设置时，客户端仍会读取 `UGSYNC_CATALOG_URL` 和 `UGSYNC_CATALOG_TOKEN`，兼容原来的试用方式。界面保存的设置优先。

目录树先显示缓存，再后台请求同一层的实时清单，并合并只存在于本机磁盘的直属目录。读取失败时会提示正在使用缓存或本机 Syncthing 索引。保存预览会尝试重新读取直属文件，并结合本机索引、磁盘文件和已有直属文件规则。目录服务覆盖 NAS 已落盘的文件，其他设备上尚未传到 NAS 或本机索引的数据可能暂时缺席。

原型缓存最近读取的 64 个目录。目录页可见时，客户端约每分钟开始一轮检查，从根目录开始，逐个更新已展开的分支。从托盘重新打开目录页、检测到系统唤醒或网络可达状态恢复时会提前检查。根目录请求失败后会提前重试，其他目录保留已显示的内容并在后续轮次重试。窗口收起或切到设置页时不发起轮询。

首次打开无缓存的目录需读取服务端。单个目录超过 10,000 条返回条目或 2 MiB 响应上限时，服务返回错误并由客户端降级。
